# 讓 Claude Code 替你部署：ADK Agent 從地端到 GCP

## 學員版實作講義：做出第一個 Agent，再交給 AI 上雲

這次實作分兩段：

1. 本機階段：說出想要的角色，由 Claude Code 寫好 Agent，學員在本機驗收。
2. 上雲階段：學員寫好規格（RUNBOOK），由 Claude Code 照規格部署到自己 GCP project 的 Agent Runtime，驗證後清理。

學員負責範圍、費用與驗收，Claude Code 負責執行。

預計時間：本機階段約 9 分鐘，上雲階段約 28 分鐘（含部署等待）。

開始前請先完成《課前準備》。

## 完成後會得到什麼

- 一個由 Claude Code 依自己描述寫成的 Agent
- 一個可以在瀏覽器對話的本機畫面
- 一份自己審過的 `RUNBOOK.md`
- 一個在自己 GCP project 跑起來、驗證後又清乾淨的 Agent Runtime

成功條件：

1. ADK Web 能開啟，能選到 `hello_agent`，問一題後 Agent 能用繁體中文回答。
2. `RUNBOOK.md` 的每一步都有指令、驗證、停止條件。
3. 雲端 Agent 能回答一題，之後 Console 的 Agent Runtime 列表是空的。

## 本機階段

本機階段全部交給 Claude Code。學員只說出想要的角色與規則，再自己驗收。

分工：

- Claude Code：寫 `course_agents/hello_agent/agent.py`、執行 `uv sync`、建立 `.env`、啟動 ADK Web。
- 學員：描述角色、自己把 Gemini API Key 貼進 `course_agents/hello_agent/.env`、問一題後改一條規則，確認行為有改變。

API Key 由學員自己貼進 `.env`，不要貼給 AI，也不要貼進聊天、投影片或 Git commit。

在專案根目錄啟動 Claude Code，把角色換成自己想要的，貼上這段提示詞：

```text
請在專案根目錄依序完成：
1. 修改 course_agents/hello_agent/agent.py，把 Agent 改成：<填入想要的角色，例如「Python 入門助教，用繁體中文，每次只解釋一個觀念並附五行內的例子」>。
   只改 description 與 instruction，不要加工具、資料庫、MCP 或其他 Agent。
2. 執行 uv sync，確認沒有錯誤。
3. 把 course_agents/hello_agent/.env.example 複製成 course_agents/hello_agent/.env，然後停下來。
   我會自己把 Gemini API Key 貼進 .env，請不要讀取或印出 .env 的內容。
4. 我說好了以後，執行 uv run adk web course_agents --port 8000，並告訴我網址。
同一個錯誤重跑一次仍失敗就停下來，保留錯誤原文。
```

學員驗收：

1. 開啟 <http://127.0.0.1:8000>，選 `hello_agent`，問一題符合角色的問題。
2. 回到 Claude Code 說出一條新規則（例如「回答最後要留一題小練習，但不要直接給答案」），請它改好後重新整理頁面，再問一次。

成功條件：ADK Web 能開、能選到 `hello_agent`、回答符合角色，而且加規則後回答行為有改變。

同一個錯誤重跑一次仍失敗就停下來，保留錯誤原文。

## 上雲階段：總覽

上雲分三步：

1. 叫 Claude Code 依 `RUNBOOK_TEMPLATE.md` 寫出 `RUNBOOK.md`（只寫不執行）。
2. 學員照三要素審 `RUNBOOK.md`。
3. 叫 Claude Code 照 `RUNBOOK.md` 部署、雲端驗證、清理。

學員不需要背任何部署指令，但要看得懂 RUNBOOK 在做什麼、會花什麼錢。

### 先做一件人做的事：設定預算警示

到 GCP Console 的 Billing，替自己的帳單帳戶設定預算警示。這一步 Claude Code 不會代做，只會提醒。

## 上雲：叫 Claude Code 寫 RUNBOOK

先確認自己的 project ID，並確認 `gcloud` 已登入。在專案根目錄啟動 Claude Code，貼上以下提示詞：

```text
請讀 RUNBOOK_TEMPLATE.md，依範本為本專案產出 RUNBOOK.md。
我的 GCP project ID 是 <填入自己的 project ID>。
只寫不執行：不要跑任何 gcloud、agents-cli 或部署指令。
寫完後停下來，等我審過再說。
```

成功條件：專案根目錄出現 `RUNBOOK.md`，而且 Claude Code 沒有執行任何雲端指令。

## 上雲：審查 RUNBOOK：三要素檢查表

逐步打開 `RUNBOOK.md`，每一步都對照下表。有任何一項打不了勾，就請 Claude Code 修改後再審。

| 要素 | 檢查項目 |
|---|---|
| 指令 | [ ] 每一步的指令完整，可以直接貼上執行 |
| 指令 | [ ] 沒有「略」「同上」「依實際情況」這類省略 |
| 驗證 | [ ] 每一步都有檢查指令與預期結果 |
| 驗證 | [ ] 雲端驗證有問一題並要求收到回答 |
| 停止條件 | [ ] 每一步都寫了失敗時的處置 |
| 停止條件 | [ ] 同一步重跑一次仍失敗就停下回報 |
| 停止條件 | [ ] 需要改權限、改 IAM、刪除非本次建立的資源時，會停下來問人 |

另外檢查費用與範圍：

- [ ] 部署指令有 `--min-instances 0`
- [ ] 部署指令有 `--max-instances 1`
- [ ] 沒有 `--agent-identity`
- [ ] 沒有修改 IAM、沒有建立 Secret Manager
- [ ] 最後有清理步驟與確認清理步驟
- [ ] 沒有修改 agent 的 `description` 與 `instruction`
- [ ] 標「需查證」的地方，Claude Code 已查證並寫明依據

## 上雲：叫 Claude Code 部署、驗證、清理

審查通過後，在同一個 Claude Code 對話貼上：

```text
RUNBOOK.md 我審過了，請從步驟 1 開始照做，一步一步執行並回報每步的驗證結果。
遇到 RUNBOOK 寫的停止條件就停下來，不要自行改做法。
```

過程中學員要做的事：

1. 步驟 1 確認 project ID 與帳單時，回覆 Claude Code。
2. 部署等待期間不要中斷，也不要同時開第二個部署。
3. 看到雲端驗證回答後，記下回答內容。
4. Claude Code 要求提升權限或改 IAM 時，先停下來，不要直接同意，舉手問講師。

成功條件：Claude Code 回報雲端 Agent 回答了一題。

### 部署卡住時

| 狀況 | 做法 |
|---|---|
| 失敗訊息很短、看不出原因 | 請 Claude Code 依 RUNBOOK 的失敗段查詳細狀態 |
| 同一步重跑一次仍失敗 | 保留錯誤原文並舉手，不要第三次重試 |
| Claude Code 想改 IAM 或開新服務 | 拒絕，舉手 |

## 上雲：清理與 Console 確認

請 Claude Code 照 `RUNBOOK.md` 的清理步驟刪除本次建立的 Agent Runtime：

```text
請照 RUNBOOK.md 的清理步驟，刪除這次建立的資源，並執行確認清理的驗證。
```

接著學員自己到 GCP Console 確認：

- [ ] Agent Runtime 列表是空的

若 Claude Code 查不到可靠的 CLI 刪除方式，RUNBOOK 會寫 Console 步驟，由學員自己在 Console 刪除。
